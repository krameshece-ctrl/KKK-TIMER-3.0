Privacy Policy

Last updated: November 2026

KKK Timer 3.0 is built on a simple principle: your solves are yours, and nobody else needs to see them. This page explains exactly what the timer stores, where it stores it, what it never collects, and how you can delete everything at any time. There is no legal hedging here — just a plain description of what actually happens when you use the timer.

If you have used other cubing timers, you may already know that many of them require an account, sync your solves to a server, or run analytics to track how you use the app. KKK Timer 3.0 does none of that. Everything you do stays inside your browser, on your own device, and disappears when you clear your browser data. This page is not a legal formality — it is an honest description of how the timer works.

The short version

  • All solve data is stored only in your browser.
  • Nothing is sent to any server owned by the timer.
  • No accounts, no cookies, no analytics, no ads.
  • You can delete everything at any time by clearing browser data.
  • The only external requests are for styling and fonts.

If you want the full details — including the exact names of what is stored, what third-party services are involved, and the technical specifics — the rest of this page covers all of it.

What is stored, and where

Your solves

Every solve you record — including the final time, the raw time before any penalties, the scramble it was solved from, any +2 or DNF penalty you applied, and the date it was recorded — is saved to your browser's localStorage. This is a standard browser feature that allows websites to store small amounts of data persistently on a user's device. It is not a server, it is not a database, and it does not communicate with any computer other than your own.

When you open the timer again on the same browser and the same device, your solves are still there. When you switch to a different browser, a different device, or a private/incognito window, they are not. That is the entire sync model: your data lives wherever you solve, and nowhere else.

Your sessions

Session names, session puzzle types, and the group of solves belonging to each session are also stored in localStorage. If you create a "3x3 Main" session and a "2x2 Practice" session, both are saved locally. Deleting a session deletes its solves permanently — there is no undo and no recovery, because there is no server to recover from.

Your preferences

The timer remembers a small number of preferences across visits: your current color theme, whether 15-second inspection is enabled, and which session you last had open. These are also stored in localStorage. They are there purely for convenience — so the timer feels like yours each time you open it — and can be reset by clearing site data.

What localStorage actually is

For readers who are not familiar with the term: localStorage is a small storage area (usually a few megabytes) that every modern browser provides to every website. It is the same mechanism that keeps you logged into websites, remembers your shopping cart, and remembers your dark-mode preference on other sites. It is local to your browser, can be inspected by you through your browser's developer tools, and is destroyed the moment you clear your browser's site data.

Importantly, localStorage is scoped per origin — meaning the data stored by this timer is only accessible to pages served from the same domain. No other website can read it, and the timer cannot read data stored by any other website.

What is never collected

The following is a complete list of things the timer does not do, and will not do:

  • No accounts or sign-ups. There is no registration, no password, no email address required, and no user profile stored anywhere.
  • No analytics. No Google Analytics, no Plausible, no Matomo, no self-hosted analytics, no tracking pixels, no telemetry of any kind.
  • No cookies. The timer does not set any cookies, either first-party or third-party. It uses localStorage instead, which is not sent to any server with each request.
  • No advertising. There are no ad networks, no sponsored placements, no affiliate links, and no commercial relationships that would involve your data.
  • No solve data sent to any server. Your solves, scrambles, sessions, and statistics never leave your browser.
  • No IP logging by the timer. The timer itself has no server to log IPs. (GitHub Pages, which hosts the site, does maintain standard web server logs — see the next section.)
  • No cross-site tracking. The timer does not use any cross-site identifiers, fingerprinting techniques, or tracking beacons.

If a future version of the timer ever adds any of these, this page will be updated first and the change will be listed at the top with a date.

Third-party services

The timer loads three external resources. None of them receive your solve data, but each may receive standard web request information (IP address, user agent, referring page) as part of how the web works. Here is what each one is and why it is present.

Tailwind CSS (CDN)

The timer uses Tailwind CSS to style its interface. It loads from the official Tailwind CDN rather than being bundled into the page, which keeps the HTML file small and makes it easy to update styles without a build step. The CDN may log standard request information. It does not receive, and cannot access, your solves.

Google Fonts

The timer uses two Google Fonts — Inter for body text and JetBrains Mono for the timer face. These fonts are served by Google's font CDN. Google may log standard request information for each font load. As with Tailwind, this is limited to network-level information and does not involve your solve data in any way.

GitHub Pages (hosting)

The site is hosted on GitHub Pages. GitHub maintains standard web server logs for its Pages service, which typically include IP address, request time, requested URL, and user agent. These logs are maintained by GitHub, not by the timer, and are governed by GitHub's own privacy policy. The timer itself has no access to these logs.

If you would prefer to eliminate even these network-level requests, you can self-host the site — download the HTML, host it on your own machine or your own server, and access it locally. Because everything the timer needs is in a single HTML file, this is genuinely simple to do, and the source code is available on GitHub.

The built-in assistant

The assistant is a chat-style helper that appears in a small panel on the timer page. It reacts to your scrambles and answers questions about cubing technique. It is important to understand that the assistant runs entirely inside your browser. Every reply it gives is generated by JavaScript code that ships with the timer — there is no AI service, no external API, no language model, and no network request involved in producing any of its responses.

The assistant's chat history is stored only in the timer's in-memory state for the duration of your visit. It is not saved to localStorage, not transmitted to any server, and not visible to anyone else. When you close or refresh the page, the chat history is gone. Nothing you type into the assistant is ever sent anywhere.

The music player

The fifty focus tracks in the timer are synthesized in real time using your browser's built-in Web Audio API. No audio files are downloaded, no streaming service is involved, and nothing about the music is tracked. When you close the timer, the music stops and the audio context is released.

Children's privacy

The timer does not collect any personal information from anyone, of any age. There are no accounts, no profiles, no chat features that transmit data, and no advertising. It is safe for children to use, and there is no data to delete or manage because there is no data collection to begin with.

Your rights

Because the timer does not collect or store any personal data on any server, the standard set of data-protection rights — access, correction, deletion, portability, objection — are all satisfied automatically. Your data is already in your hands, already correct, and already deletable by you whenever you choose.

If you are covered by the GDPR, the CCPA, or any other privacy regulation, the practical answer is the same: the timer holds no personal data about you on any server, so there is nothing to request and nothing to delete from us. The data you do have is stored locally on your device and is under your control.

How to delete your data

You can delete every solve, session, and preference the timer has stored at any time. The exact method depends on your browser, but the general steps are the same everywhere:

  • Chrome / Edge: Settings → Privacy and security → Site settings → View permissions and data stored across sites → find the timer's domain → Delete.
  • Firefox: Settings → Privacy & Security → Cookies and Site Data → Manage Data → search for the timer's domain → Remove.
  • Safari (macOS): Settings → Privacy → Manage Website Data → find the timer's domain → Remove.
  • Safari (iOS): Settings → Safari → Advanced → Website Data → find the timer's domain → swipe to delete.

In most cases, simply clearing all browser data for the site works too. Once cleared, deleted data cannot be recovered — there is no backup, because there was never a server to back up to.

Changes to this policy

If this policy ever changes — for example, if a future version of the timer adds a feature that requires new data handling — the change will be listed at the top of this page with a date, and the previous policy will remain accessible for comparison. The current commitment is simple: no accounts, no tracking, no ads, and no data leaving your browser. That commitment is not expected to change.

If you have a question about this policy, notice something that seems inconsistent with what the timer actually does, or want to suggest an improvement, please open an issue on the project's GitHub repository. Questions and corrections are welcome.
